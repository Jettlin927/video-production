# 排版动画视觉系统与 Remotion 工程

`layout-plan.json` 是唯一的画面事实来源：配音、字幕、动画、配图全部消费它。先写完计划再建工程，不边渲染边想排版。

## 视觉层类型

| 层 | 用途 | 默认动效 |
|---|---|---|
| 大标题层 | hook、最大结论 | 打字机逐字出现＋光标 |
| 陈述行 | 论据、铺垫 | 整行淡入＋轻微上移 |
| 对比行 | 痛点、新旧对照 | 旧行先出，新行紧随其后，色彩分级 |
| chip 组 | 关键词、公式化方案（A+B+C） | 逐个点亮（灰→实色），间隔约 0.4s |
| 配图层 | 佐证、示意图、场景图 | 淡入＋缓慢推近，约 2–3s |
| 引用条 | 资料摘录、用户原话 | 整层淡入，左侧色条 |
| 底部字幕条 | 配音转写（可双语） | 随句切换，无动画 |
| 常驻栏 | 头像＋栏目名（可选） | 无动画，全片固定 |

## 三区安全区（横屏 1920×1080 参考值）

画面按纵向切成三区，任何内容不得跨区堆叠，否则文字与素材会互相压住：

| 区 | 纵向范围 | 放什么 | 禁止 |
|---|---|---|---|
| 主画面区 | 0 – 900 | 主文案、对比行、chip、大数字、配图、实拍素材 | 压到字幕分隔线以下 |
| 字幕分隔线 | 900 | 1px 细线，全片固定 | 素材或文字穿过 |
| 字幕區 | 900 – 1080 | 中文字幕（上）＋英文字幕（下），居中 | 放任何素材、chip、图标、水印 |

- `subtitle_rule_y` 是硬边界：**素材层的下边缘必须 ≤ `subtitle_rule_y`**，不能伸进字幕区，也不能被字幕区遮住。
- 字幕区高度按最多两行中文＋两行英文预留；`subtitle_zh`／`subtitle_en` 字号改大时同步把分隔线上移，不允许字幕顶到画面底边。
- 竖屏按同样思路把字幕区留在底部安全区内，另核平台 UI 遮挡。

## 证据链素材的位置

"证据链"指实拍画面、资料录屏、截图、清单这类支撑可信度的素材。位置由用途决定，但都受三区约束：

| 用途 | 位置 | 处理 |
|---|---|---|
| 右侧栏证据（竖版实拍、人物剪影） | 右栏，底部对齐分隔线上方 | 不铺满整屏 |
| 背景氛围（现场全景） | 主画面区全幅做背景 | 降不透明度至 0.25–0.35，文字所在处仍可读 |
| 资料面板（录屏、清单、表格） | 主画面区内左侧或右侧面板 | 与文案分栏，**不得压到文案下方或被字幕遮住** |

- **证据素材必须整体完整，不能被字幕条切掉一条**：宁可缩小、裁切或改放右栏，也不允许"素材压到字幕区、字幕盖在素材上"。
- **证据素材的重心在主画面区，不是底部**：素材面板的上边缘靠近 `content_top`，下边缘 ≤ `subtitle_rule_y - 24`。把资料面板贴着画面底部放，必然压到分隔线并和字幕抢位置，这是最常见的错放。
- 竖版素材的可见比例也要核对：9:16 现场视频放进 16:9 右栏时必须按容器高度反推宽度（`宽 = 高 × 画幅比`），不能按整屏宽度缩放，否则素材会被字幕条或画面底边截断。
- 只用**主画面区**承载证据，绝不用字幕区；横屏竖版素材（9:16 现场视频）优先放右栏，而不是铺满 16:9 拉变形。
- 素材是真实证据时在计划里记录来源与它证到什么，并且**不把它当作具体数字的证据**；示意素材明确标注。
- 素材与文案同屏时保证对比度：深色素材上的文字加浅色底或描边，浅色素材上的黑色剪影加白色外发光。

## 字幕分页与排版

- **一条字幕 ≤ 18 字**；超过就按标点（，、；：？！）就近切成多页，页与页之间用该句的配音时间按字符数比例分配，**不压缩也不重复**。
- 一句话最多排两行；两行仍超过 18 字/行时按标点再分一页，而不是缩字号。
- 英文一行 ≤ 48 字符，超过按语义断行；不按字符硬切单词。
- 每页至少停留 0.8s，避免短句闪页；分页后的每页与其配音片段严格对齐。
- 中英双语时中文在上、英文在下，两行都居中；英文不承担强调色彩。
- 分页规则写在生成 `layout-plan.json` 的脚本里（`caption_pages` 思路），组件只消费最终页，不在组件里临时切句。
- **字幕把一句话原样铺成两行是最典型的排版事故**：用户会把整句读完再抬头看画面，配音已经进到下一句。必须先分页，再检查每页字数与行长；分页不是可选项，长句默认就要拆。
- 分页与行长用 [check_hook_plan.py](../../video-production/scripts/check_hook_plan.py) 机检（`caption_long`／`caption_lines`），不靠肉眼抽查。

## 堆叠与清屏

同话题的层留在屏上向上堆叠——屏幕是一张纸，信息越堆越多；话题切换时清屏。单屏层数不超过 4 层，超过时拆屏或合并。最大结论（主题色）出现后不再被新层压住，直到清屏。

## 节奏与信息密度

屏幕停留时长由配音实测决定，但"时长合理"不等于"看着不慢"。同一屏内不允许出现无视觉变化的死区：

- **配音气口必须先收紧再排时间轴**：TTS 整篇合成会在每个标点留下 0.3–0.9s 停顿，一条 50s 的片子能有 10s 以上是静音，这正是"节奏太慢"的主要来源。合成后按 [tts.md](tts.md) 的"收紧气口"步骤压缩停顿，再用压缩后的音频重算所有帧号；不允许直接用未收紧的整篇 TTS 排时间轴。
- **目标时长与参考片挂钩**：用户给了参考样片时，成片时长先对齐参考片；文案比参考片长而必须超时，在 `production.json` 写明超出幅度与原因，并把气口收到最短，而不是默默拖长。
- 前 5s（hook 窗口）必须有 ≥ 3 个视觉事件：不允许"一句话打完字才动下一个元素"。
- 单屏连续 **≥ 2s 没有任何新的视觉事件**时，必须插入一个事件：新层出现、强调词点亮、chip 点亮、配图推近、背景位移，或清屏换屏。
- 每屏至少 **3 个视觉事件**（不含字幕翻页）；信息量大的屏把大数字、chip 拆成逐个出现，而不是一次全部显示。
- 打字机逐字速率控制在 0.04–0.08s/字；整句打完不晚于该句配音结束。逐字过慢是第二个常见拖沓来源。
- 层入场动效 8–14 帧收完（30fps 约 0.3–0.5s），不允许用 20 帧以上的慢淡入把节奏拖软。
- 相邻两屏必须换版式或换背景，不能连续两屏只有文字位置变化。
- 视觉事件密度记录在 `layout-plan.json`，用 [check_hook_plan.py](../../video-production/scripts/check_hook_plan.py) 机检（`dead_zone`／`screen_events`／`hook_events`／`duration`），验收时按事件帧抽帧核对，不只看每屏首帧。

## 色彩与字体

- 色彩语义按 [copy-model.md](copy-model.md) 的默认值或当次 `style.json`；强调词颜色逐句绑定，组件不吃全局关键词表。
- 字体按主 Skill [fonts.md](../../video-production/references/fonts.md)：大字标题用思源黑体 Bold；装饰性短重点可用站酷类字体，长陈述不用装饰字体。渲染前等待字体文件真实加载（`@remotion/fonts` 或 `loadFont`），再按真实字宽检查换行。

## 工程约定

- 输出目录内建独立 Remotion 工程，锁定依赖版本；画幅与 fps 按 `style.json`（参考值：横屏 1920×1080@30 或竖屏 1080×1920@30）。
- 单一帧时钟：所有动画用 `useCurrentFrame`；秒→帧在生成计划时统一舍入，组件只消费帧号。
- 安全区：四边 ≥60px；按上文三区划分主画面区与字幕区；竖屏按目标平台安全区另核。
- 素材用 `staticFile` 引用本地文件；生成配图先经主 Skill 的生成→下载→审查流程再进工程。

## 组件清单

[assets/remotion](../assets/remotion) 提供起步模板，props 以帧号和样式对象为主，颜色字号由 `style.json` 经 props 注入：

- `TypewriterLine`：逐字出现＋光标，按 `startFrame`/`perCharFrames` 驱动。
- `KeywordChips`：chip 组逐个点亮，支持分隔符（如 `+`）与逐 chip 颜色。
- `BilingualSubtitleBar`：底部中英双行字幕＋上分隔线，按句切换。

这些是模板组件：首次实片渲染后按实际效果校准（字号、间距、动效曲线），校准结果回填组件再复用。
