# 钩子脚本结构模型

钩子视频是"动态 PPT"：屏幕像一张纸，论据逐层堆叠，观众跟着配音读完一个论证。脚本先满足论证结构，再谈排版。

## 六段结构

30 秒约 6–8 屏，每句归属一个屏幕角色：

| 角色 | 任务 | 时长预算 |
|---|---|---|
| hook（结论前置） | 一句话给出最大结论或反常识断言，制造"为什么" | 3–5s |
| 论据 | 政策、趋势、数据方向，给结论一个支点 | 5–8s |
| 痛点对比 | 旧做法的困境，与新方向对照 | 5–8s |
| 方案 | 给方法，适合公式化表达（A+B+C 的 chip 串联） | 6–10s |
| 佐证 | 资料、案例或成果画面，支撑可信度 | 3–5s |
| cta | 一个动作：关注、评论、领取、私信 | 3–5s |

顺序可按题材调整（痛点前置也常见），但 hook 必须在 3 秒内给出留下来的理由，CTA 只有一个动作。

## 逐句标注

每句在 `hook-script.json` 里带：

- `id`：稳定句 ID（s01、s02…），后续配音、排版、质检全部引用它。
- `role`：上表六种角色之一。
- `text_zh` / `text_en`：中文文案与英文翻译；英文以达意为先，不按字对译。
- `emphasis`：本句强调词，逐句从数字、对比、动作、结论里选，不交全局词表匹配。
- `layout_hint`：排版意图（大标题 / 陈述行 / 对比行 / chip 组 / 配图占位 / 引用条）。

屏与句的关系：同话题的句堆叠在同一屏，话题切换才清屏；一句信息量大的可独占一屏。

## 文案纪律

- 数据、政策、承诺来自用户资料或用户给定的方向；表达策略性断言（如"下一个风口"）可以写，具体收益数字、排名、政策条款细节不编造。
- 佐证段出现的截图/资料画面须真实存在或明确为示意图；示意图在 `layout-plan.json` 标注，不冒充真实证据。
- 文案时长用朗读校验：中文配音约 4–5 字/秒，30 秒成片正文约 120–150 字。

## 时长口径与语速

时长有两条口径，不要混用：

1. **素材时长**（保留用户原文全文）：正文按配音实测走，用户给多少文案就配多少。这类成片只要求"语句之间不留空档"，不承诺落在 20–40s。
2. **目标时长**（用户给了明确秒数，或要求对齐参考片节奏）：以目标时长为硬约束，反推语速与删改幅度：

| 手段 | 取值 | 说明 |
|---|---|---|
| TTS 语速 | 1.0–1.25 | 超过 1.25 中文听感变赶，宁删文案不加速 |
| 句间停顿 | 0.05–0.15s | 默认不留停顿；文案自带逗号时不再额外加气口 |
| 片尾停留 | 0.5–1.0s | 只留够读完 CTA，不留 1.5s 以上 |
| 删改文案 | 优先删修饰语和重复论证 | 保留结论句、数字句、CTA 句不动 |

- 参考片对齐时**先量参考片语速**（正文字数 ÷ 成片时长），再用同语速反推本文案的成片时长；节奏差主要是语速差，不是屏数差。用户说"节奏太慢"时先查语速与句间空档，不要先删屏。
- 文案必须删改时先在 `hook-script.json` 记录 `copy_edits`（删了哪句、为什么），用户给定原文默认不动。

## 双语字幕分工

底部字幕是配音的转写（完整句）；屏内大字是排版层（提炼后的短句与强调词）。两者不互相替代：大字不逐字复述配音，字幕不承担强调色彩。

**一条字幕不得超过 18 字**。长于 18 字的句子必须按标点分成多页，页内仍保持原句语序与用词；分页办法与时间分配见 [layout-motion.md](layout-motion.md) 的"字幕分页与排版"。英文一行不超过 48 字符。

## 色彩语义（默认值，style.json 可覆盖）

- 黑：陈述与铺垫。
- 红：结论、对比、痛点。
- 橙/主题色：全片最大结论，一条视频只用一到两次。
- chip：未点亮灰底，点亮后黑底或红底白字，按点亮顺序逐一变色。
