# 证据链、解释画面与节奏空镜

在内容取舍和 final 时间轴确定后、生成素材前读取。目标是帮助观众理解并评估原声观点；口播原声、独有内容、关键表情和收尾继续保留。只给 raw＋风格时，Agent 自行完成下列决策，无需让用户逐项填表。

## 1. 逐段判断用途和匹配关系

读完整保留文稿，再按原句及相邻上下文选画面。把“观众不相信什么/不理解什么、画面具体补充什么”写清楚；仅共享关键词不能算匹配。

| purpose | 用途 | 来源与判断 |
|---|---|---|
| evidence | 真实证据链：支持可核实的经历、产品或事实 | 对应真实文件 `local_real`；写明来源、片段和证据能支持的范围 |
| explanation | 解释概念、流程、对比或场景 | 可生成 `generated`、排版 `template` 或用真实素材；不能暗示未证实的交付或效果 |
| pacing | 与当前话题有关的节奏空镜 | 低阅读负担的场景/图片；作用是调节观看节奏，不承担事实证明 |

四项匹配检查：主体是否对应、动作是否对应、关系是否对应、画面暗示的事实是否超出依据。真实来源本身也不保证足够证明原句。

- “每期100个学员”：课堂画面只能证明画面中的上课场景；人数与“每期”需对应记录，不能以人多的 AI 图补证据。
- “智能体整理客户信息”：展示“零散沟通记录→结构化客户卡片”可作解释；机器人头像只能表示一个名词。
- “这是我们给客户交付的系统”：用对应真实录屏，并说明其能展示的功能；界面图不能单独证明实际交付或业绩。
- “反复整理表格很耗时”：卡通人物在表格间切换可作解释/空镜，避免虚构节省比例。

没有真实证据时保留口播，记录 `evidence_gaps`，可另选明确标示的解释图。首版读取用户提供的本地真实素材；NAS 扫描和网页素材采集需另有实现与本次任务范围。只有讲述内容时不自动改写成更强的承诺。

## 2. 选择落点与时长

优先放有解释价值或确有证据的画面，再检查剩下的连续真人段：距上个补充画面结束约20–30秒时，在附近完整语义位置寻找候选。已有解释/证据画面覆盖的区间无需再补空镜；这是检查阈值，不是按时间强制插图。

普通图片先取2–3秒；复杂图表、录屏依据实际阅读所需时间调整或简化。开场核心句、关键结论、情绪/手势和收尾优先回真人。找不到相关画面、会打断论证或预算不足时跳过。反光严重等局部视觉问题可用相关画面覆盖；音频错误仍需直接修复。

在 `broll-plan.json` 的 `decisions` 中记录候选的原句/词 ID、final 区间、insert/skip 和理由；实际入片项写入 `jobs`。不要为了填满时间而给每句话生成图片。每个 job 的原句/词 ID 应与当前 final 转写核对，按说到的概念落点安排帧区间。

## 3. 锁定整片视觉风格

在 `style.json` 的 `visual_style` 保存一次整片规范，并原样复制到生成计划。优先沿用用户定调或提供的基准图；否则从 [visual-styles.md](visual-styles.md) 的预设里**选一套**适合本片内容的，用 `visual_plan.style_preset(id, aspect)` 生成字段，不要每次即兴写一套。选型依据是文案内容和片子质感，并把选它的理由写进计划。

**一条片子只用一套预设**：`style_id` 必须等于计划的 `visual_style.id`，脚本会拒绝混用。

**画幅跟随成片**：竖屏成片出竖幅（aspect=`portrait`），横屏成片出横幅（aspect=`landscape`）。不要把横幅素材塞进竖屏全屏——contain 会留下大片黑边，除非版式本就打算做通栏条带。

**不要用卡通插画做商务口播的默认风格**：扁平二维插画只在内容本身轻松科普或面向儿童时才合适，财务、经营、行业和 B 端题材用它会显得不专业。

规范字段：`id`（风格版本）、`medium`（如写实摄影/三维科技概念/产品界面）、`palette`（主辅色）、`rendering`（线条、材质、光影）、`composition`（构图、画幅和字幕留白）、`avoid`（需要排除的风格和元素）。重复出现的人物、物体在 rendering 中固定外形要点。预设与选型表见 visual-styles.md。

先生成一张有代表性的图片，实际查看并选择合格版本。第一张定下什么语言，后续生成图片就保持相同语言；首张不合格时先修正，不把偶然跑偏当作基准。将选定图片的本地路径和哈希记为 `style_reference`，再生成余下图片。用户已有合格基准图时可直接使用。

每条 prompt 描述主题、当前句及上下文、画面目标、主体/动作/关系和不得暗示的事实；共享视觉规范由脚本统一加入所有生成请求。具体画面可变化，画风保持一致。图片优先；仅需呈现动作或时序时生成视频，其美术风格也沿用整片规范。金额、准确文案、图表和箭头用本地模板排版，不依赖生成模型画字。

当前模型适配器只有文本提示词合同，没有已验证的参考图输入或 seed 参数。基准图目前用于实际视觉对照，不能声称已发送到生成模型，也不能靠同一提示词保证一致。用工具查看每张图片并与基准图比较媒介、色调、线条/材质、人物设定和构图；查看视频动态内容。合格后记 `style_review=pass`、具体 `style_review_notes` 和 `style_reference_sha256`。没有视觉检查能力时记 not_checked，暂不入正式成片。

真实证据保留原始可信内容，可统一边框、背景和排版，不将真实截图或现场照片重绘成卡通来追求一致。整片生成素材统一画风与真实证据保持原貌可以同时成立。

## 4. 成本、失败与验收

每条视频使用同一生成输出目录，校准、分批生成和重生成都累计入该目录的状态账本。用当前已知的服务报价填写 estimated_cost 和来源；未知时先做清单，不使用讨论录音中的历史金额冒充现价。预算不能代替付费授权。数量、估算金额和同镜头尝试次数均有上限；一次重生成沿用 shot_id、使用新 id。超时/结果未知沿用原任务查询，停止盲目新建。

画风不符先调整具体 prompt，在既有授权和预算内有限重生成；达到上限则跳过可选空镜，列出缺口。同一输出目录用 `.visual-style.json` 锁住跨批次画风，换素材 ID 也不能绕开。整片确需改画风时，显式更新 visual_style.id，在计划写 style_change_reason，仍沿用原费用账本；最终计划只用新风格的生成素材，并选择新基准图、重新审查。真实证据不足不能靠重生成补足。

入片前检查 asset_review（原句匹配、事实范围、清晰度/畸变、文字）和 style_review（与基准图一致）两个维度。脚本校验只证明记录完整、版本一致、预算和来源约束成立，不证明审美或事实判断正确。切点、原声和字幕沿用同一时间轴，生成视频保持静音。

首轮升级验证用同一原片的纯口播版和加素材版对照，连续观看：理解是否更容易、有没有误导、图片是否抢戏、能否读懂、返回真人是否自然。记录生成数量、重试、估算/实际费用（实际未知就保留未知）和人工返工。完整交付与听审规则沿用 talking-head-cut；未实际观看不得宣称说服力提升。
