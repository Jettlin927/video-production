# PPT 运镜讲解

本 Skill 是 [video-production](../video-production/SKILL.md) 的子流程。把 PPT 当作被介绍的产品：以有留白的背景承托悬浮页面，观众先认识结构，再跟着讲解者的鼠标探索重点。PPT 是内容载体，不限定 PowerPoint 软件；可使用已有幻灯片、白板、长页或按文案重建的可编辑页面。录屏软件式运镜是视觉语言，不要求实际录制桌面。

输入最少为主题或文案；已有录音／页面也可复用。默认 one-shot：Agent 自行完成脚本、配音、信息地图、运镜、渲染与自检，直接交付 MP4，不让用户逐页确认或接手剪工程。one-shot 是一次需求完成制作，不是承诺一次模型调用；资源、权限或关键内容缺失时仍须明确阻塞。参考视频只供风格学习，不自动授权照搬文案、声音或商业承诺。

本路线默认 `export_format: "mp4"`，不生成、安装或验收剪映草稿，也不把工程缺失当失败。渲染代码与计划仅留在项目中供内部重试，不要求用户编辑或接收工程。平台上传／发布仍需另有明确授权。

## 1. 接收与路由

- 主 Skill 已通过环境门时复用报告；直接调用且尚未检查时运行主 Skill 的 `video_production.py check --workspace-root <workspace-root>`。不复制配置、不重新安装依赖。
- 新项目通过统一 CLI `init --route ppt-screencast` 建立，沿用主 Skill 的 [工作区规范](../video-production/references/workspace-layout.md)。已有工程返工保留原项目和输入文件；历史 route 的调整记录原因，不为了分类搬动交付。
- 只给主题时先写有清晰判断和行动落点的文案；不编造收益数字或案例。只给文案时保留独有论点和顺序。没有风格要求时默认1080×1920、24fps、柔和渐变背景＋白色悬浮页面、内置Noto Sans SC、克制配色和普通TTS；按已有配置选择声音，不擅自克隆声线。可逆缺省由Agent处理，不向用户发一张参数问卷。
- 产品演示风格参考 OpenScreen，首次制作读 [product-demo-style.md](references/product-demo-style.md)。借鉴背景留白、圆角阴影、平滑焦点切换和连续指针，不复制编辑器界面、网站文案或参考壁纸，不额外安装录屏软件。
- 参考成片与本次内容分别登记。首次处理这种参考时读 [reference-analysis.md](references/reference-analysis.md)，在片头、段落切换和结尾抽取连续短窗，区分整页、聚焦、鼠标操作和回全景；静帧不能证明精确运镜曲线。
- 画幅按用户或平台确定，不把参考片的比例硬编码成所有视频的默认值。白底、手写字体、红绿配色是本次参考的选项，不是类型定义。

完成条件：内容源、风格源、画幅、输出范围与授权边界分清；公共环境报告可用。

## 2. 把讲解变成信息地图

- 沿用用户论点、例子和顺序。只有用户要求压缩文案或制作短钩子时才改成短视频脚本；本类型没有默认 30 秒时长。
- 先确定每段的判断、数字、对比、列表或关系，再规划页面。旁白可以完整，屏幕只保留关键词、短句和关系图；用 `narration_id → page_id → target_id` 记录每句关注位置。
- 文案是事实源，已有 PPT 是可重构素材，不是只能换皮的成品。逐项决定保留、摘要、拆分、合并或删去无关项；每项明确要表达的判断，再选文字、对比面板、流程、数值卡或关系图。不能只改标题、给旧页面加几个圈，也不能所有主题套同一组空泛卡片。保留数字、单位、否定、条件和例外；没有量化来源时不画虚构比例图。
- 在 author 中登记 `script.sentences[{id,text_zh}]`；每个内容元素（rule 除外）填写 `source_ids` 与 `takeaway`。前者追溯原文，后者说明这项视觉要让观众理解什么。编译器拒绝缺少来源／表达意图的内容项，但来源引用有效不等于语义正确，Agent仍逐项核对摘要与原文。
- 一个语义段尽量在同一页展示关联信息：先出现整体结构，再聚焦一个目标，比较时保留两方，换话题再换页或滚动到下一组。按内容决定何时揭示元素，不把全文纵向堆成匀速滚动字幕。
- 给每个强调目标建立稳定 ID 和页面坐标包围盒。新建或需要整改的页面用可编辑文字／矢量图重构；既有 PPT 的高分辨率画面仅在内容已对应文案时复用，不能以截图不可编辑为由跳过逐项整改。无法可靠识别的文字明确阻塞；真实截图与示意图分别标注来源。
- 将页面坐标、目标、语义理由及对应句子ID写进 `work/content-authored.json`；格式和调用读 [motion-plan.md](references/motion-plan.md)。执行 `screencast-build --content ... --script ... --timing ... --audio ... --workspace-root ... --out ...`，由公共工具绑定场景、强调、字幕时码并派生镜头。Agent只编辑本次内容JSON，不另写emit_author、分页、排布修补或关键帧脚本。窗口装不下时合并目标／减少动作，不把强调挪到别句上。

完成条件：每个讲解段有视觉落点；页面表达关系而不是复写旁白；目标坐标对应实际渲染内容。

## 3. 锁定讲解时间轴

- 用户明确要求克隆声音时读主 Skill 的 [公共声音克隆](../video-production/references/voice-cloning.md)：确认声源与调用授权，首次 `voice-create` 保存音色记录，后续直接 `tts --voice-record`。不从风格参考视频擅自取声，不给本路线另写克隆执行器；仍沿用下面的转写／对齐时间轴流程。

- 优先复用用户录音或已确认的配音、转写与时间轴，不为换视觉重新生成声音。需要转写时读主 Skill 的 [ASR 流程](../video-production/references/asr.md)。需要新配音时读主 Skill 的 [公共 TTS 执行器](../video-production/references/tts.md)，通过 `video_production.py tts` 从本次文案直接生成配音及句子数据，再转写／对齐；不另写分句、配音调用或拼接脚本，不查询旧项目的配音实现。实际付费调用仍受当次授权约束；声音克隆另核对声源授权。
- 有脚本与词级时码时用公共 `align` 生成句子时间；字幕以内容源为准，ASR提供时码。PPT不默认压气口；确有节奏需求时用 `tighten` 明确指定停顿策略，再对齐其重映射词表。改声音后重建同一份绑定计划，不继承钩子固定气口目标，不在生产会话修改对齐器或音频工具。
- 每次强调记录旁白起止、目标、意图和最终帧区间。安排“镜头到位 → 指针到位 → 指向／画线 → 停留阅读”。重点落在重音附近；稳定阅读期间允许画面静止。
- 字幕固定在屏幕层、短语分页，按主 Skill 的 [字体参考](../video-production/references/fonts.md) 检查实际字形；与页面内容分区，不随页面缩放或滚动。

完成条件：画面动作和字幕消费同一个 revision；时长由讲解与阅读需要确定，而不是动画模板决定。

## 4. 制作语义运镜与鼠标强调

- 镜头主要使用三个动作：全景建立关系、局部推近读清重点、平移／拉回恢复上下文。zoom 围绕目标，不围绕画布左上角；切换焦点用缓入缓出，避免漂移、反复抽动或全程匀速滚动。
- 缩放量以可读性和上下文为准。不要把单个字放大到丢失判断；对比时两方都应在视口内。运镜停稳后才开始圈画，复杂关系给读图时间。
- 鼠标是讲解者的手：整段保持可见，从页面空白处平滑走到重点，跨目标时沿连续路径移动，圈画后停留阅读，再跟随讲解去下一项。不能到每个重点才凭空出现，也不无意义地绕全页乱转。一次强调一个主要目标；圈注包住整段重点，划线沿词组下沿，指向不遮住文字。标记随页面一起变换并保留到场景结束；鼠标保持屏幕尺寸，尖端跟随绘制路径。
- 固定模板 [Screencast.tsx](assets/remotion/Screencast.tsx) 消费页面数据，复用 [CameraStage.tsx](assets/remotion/CameraStage.tsx) 与 [motion.mjs](assets/remotion/motion.mjs)。它支持本路线现有文字、chip、数值、面板、流程、列表、引用、条形图和分隔线；本地字体加载后按真实DOM尺寸把内容适配到计划框，过密时明确报错而非裁掉文字。不要为每条片再写TSX、字体测量或新的渲染器；有明确超出模板的视觉需求时才扩展并验证。
- 渲染前运行统一 CLI `screencast-check --plan <screencast-plan.json> --out <qc/plan-check.json>`。它逐帧检查强调目标是否出视口、时间区间和引用等；不把“结构检查通过”当作画面或语义通过。

完成条件：计划检查通过；用公共 `screencast-preview` 渲染全页概览／回全景和每个强调的绘制中帧，检查指针、标记、字体与对比双方。按生成的review-draft逐页比对原文及画面，记录证据和问题；修复后重新预检与审核。发现问题批量改内容JSON，不写stills／verify脚本，不改变验证规则消除失败。

## 5. 导出与验收

- 语义和画面审核通过后，运行 `screencast-deliver --workspace-root ... --plan ... --audio ... --out-dir ... --review <review.json>`。完整预检、逐页审核和当前快照指纹是整片渲染的前置门；未审、旧审核、局部预检或未解决high/medium问题会拒绝渲染。不要先开长渲染、同时发现内容问题再取消返工。独立复核确有需要时也放在渲染前，提供review数据包，让复核员填写结论而不是新写验证程序。
- 交付消费同一冻结快照，复用已通过的预检 → 整片渲染 → 混流 → 技术QC（含固定短窗音轨一致性）→ MP4交接。不调用剪映；不边渲染边修改计划，只有内容／声音／版式改变才重渲染。画面审核及听审仍不由技术QC自动证明。
- 公共入口快速返回后台job。用宿主后台结果或 `job-watch` 等终态，再读 `output/handoff.json`；不在等待期间不断读状态／写sleep脚本。音频时长与计划不符时重建讲解时码，不自动截断或变速。语义、素材或版式变动才重渲染；仅报告或检查规则变化不应靠重剪整片掩盖问题。
- 全片可解码与规格正确之外，需要连续动作抽查时用公共 `sample` 提取少量原帧范围，观看推近、平移、圈画和回全景，不另写抽帧／音轨对比脚本。核对数字、否定和条件对应目标；无法执行的视听项保留 `not_checked`。
- `qc.json` 区分计划、渲染、语义／视觉和听审，各项使用 `pass / fail / not_checked` 及证据。后台 `technical_ready` 只证明生成与文件检查；Agent还须完成内容与代表画面的自检。画圈、鼠标和字幕本来会动，不能用包含这些区域的整帧差异来判“镜头不稳”；复用公共镜头数学检查和模板预检，不每条视频现写verify_video。

默认对用户只交付最终MP4及简短验收说明。用户明确需要时才附SRT／内部计划；不附剪映或Remotion工程。目标是可发布的完整视频，不是把粗剪和调参责任交给用户；存在重要未检项时如实说明，不能把技术通过宣称成语义／视觉质量通过。

## 本 Skill 的验证边界

仓库提供可运行的技术夹具 [demo-plan.json](assets/demo-plan.json)、公共模板及离线测试，仅供组件与几何回归，不是业务视频答案。旧计划仍可检查／交付，新增 author 编译必须填写来源和表达意图。结构检查不能证明语义、视听质量、DeepSeek one-shot 成功率或 Token 收益；这些指标须使用新输入独立评估。
