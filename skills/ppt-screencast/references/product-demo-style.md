# 把 PPT 当成产品来介绍

使用 OpenScreen 式产品演示方向时读本页。参考项目：https://github.com/getopenscreen/openscreen；官方交互演示：https://getopenscreen.com/ 。参考只定义视觉方向，不提供业务文案或成片答案。

## 取什么，不取什么

取背景留白、悬浮白色内容窗口、圆角与阴影、清晰的屏幕尺寸指针，以及聚焦前后的稳定阅读。OpenScreen 的点击式自动 zoom 可借鉴“先到位，再展示重点”，但这里按旁白语义安排，不依赖真实录屏点击。

不制作一个“介绍 OpenScreen 的视频”，不绘制编辑器时间轴／侧栏，不添加摄像头小窗；不复制参考壁纸或业务文案。本仓库独立实现模板，不依赖安装 OpenScreen，不搬用它的代码。默认渐变背景轻、页面白、墨色文字，强调色控制在一至两种。

## 每段的制作顺序

1. 从原文提取本段要说清的判断，保留数字、条件和否定。
2. 逐项重构页面：对比用并列面板，步骤用流程，可信数字用数值卡，关系用结构图；无来源的比例不能当数据。
3. 全景先让观众知道这张 PPT 在讲什么，再推近当前目标；讲对比时保留两方，讲完拉回关系全景。
4. 一个连续鼠标沿讲解顺序到重点，指向／圈画／划线后停留；圈画留在页面上，随页面一起运动，换段清除。留出跨目标移动的空档。
5. 看实际文字、指针、标记的连续效果，再决定是否合格；不要以“用了渐变和 zoom”代替内容自检。

固定模板已实现窗口包装、屏幕轨迹与场景内标记保留。每条视频只写 author 数据，不改 TSX／轨迹数学。需要新增视觉表达时扩展公共模板并验证，不在项目中复制一个新渲染器。

## 内容整改检查

对每个内容元素回答：来源是哪句文案？观众要理解什么？当前形式比照抄原句更容易理解吗？数字和判断是否一致？箭头是否真的表示原文的顺序或关系？缺少来源的旧 PPT 项删去或重新论证，不因参考图里有一个模块就保留。

编译器检查 source_ids 与 takeaway，只能阻止无追溯项和漏填项；不具备语义判真能力。内容核对、实际字体排布、遮挡及阅读节奏必须在 Agent 自检中完成。
